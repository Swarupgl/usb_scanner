Applying Embedded AI algorithms and constraints taught by Dr. Dubacharla Gyaneshwar directly to MalConv

Quantization Slides 94, 103-108

Reducing weight precision from FP32 (4 bytes) to INT8 (1 byte). Slide 108 notes that quantization trades off complexity (speed) and fit to data. In MalConv, ONNX Dynamic Quantization reduces weight storage footprint by 25.7% (from 4.1MB to 3.0MB) without loss in accuracy.

q = clip( round(w / S) + Z )

Weight Pruning Slides 92-93, 111

Pruning removes less salient weights by zeroing them out based on L1-magnitude magnitude. Slide 46 highlights that pruning reduces compute density. By zeroing 75% of weights in Conv and Linear layers, we reduce active arithmetic computation (non-zero MACs) from 537M to 139M, saving device energy.

||w|| < Threshold → w = 0

K-means Weight Sharing Slides 114, 116

Weights are clustered into k groups; all weights in a cluster share the same centroid value. Instead of storing 32-bit values, we store 4-bit indices (k=16) and a 16-centroid codebook. This shrinks MalConv's memory footprint by 87.5% (down to 521 KB!), perfectly fitting low-cost MCUs.

Centroids: c_i → Index bits: log_2(k)

Sequence Downscaling Slides 40, 41, 46

Reducing sequence length reduces conv operations linearly. Since MalConv utilizes Adaptive Max Pooling over Conv activations, the network remains fully length-independent. Reducing scanned prefix size from 256KB to 32KB cuts conv MACs by 8x, slashing latency from 9.9ms to 1.82ms!

MACs ∝ max_len / window_size
